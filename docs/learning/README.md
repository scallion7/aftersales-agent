# 分层项目教学

[文档中心](../README.md) · [当前验收](../evaluation/acceptance.md) · [项目展示与面试](../showcase/README.md)

这套课程围绕一个具体问题展开：客户想退货，系统如何查清政策、收齐材料、取得确认，并在中断后继续可靠地处理。学习对象是已有 Python 基础、希望完成 Agent 应用开发与工程验证的读者。项目维护者为 [scallion7](https://github.com/scallion7)。

课程基于当前完整实现进行代码阅读、运行观察和小步扩展。每个实验先运行现有回归，再写一条新的行为测试并解释证据；完成课程不等于已经从零独立实现仓库全部功能。原第 1–34 期继续保存在[历史目录](../history/README.md)，用于理解演进背景，其历史命令不作为本课程的执行入口。

## 学习路线

先完成[环境准备](setup.md)，再按下面的顺序进行。时长是建议学习安排，不是已经测得的完成时间；每个实验可以拆成阅读、运行、作业三个学习时段。

| 层次 | 实验 | 学会什么 | 建议安排 |
|---|---|---|---|
| [第一层：基础机制](level-1-foundations.md) | L1-01 模型边界；L1-02 工具与 MCP；L1-03 政策检索 | 用受控输入解释 Agent、工具调用和引用的关系 | 每实验 45–60 分钟 |
| [第二层：业务流程](level-2-workflows.md) | L2-01 多轮申请；L2-02 可信确认；L2-03 策略与人工协作 | 把自然语言意图接到持久化业务状态 | 每实验 60–90 分钟 |
| [第三层：可靠执行](level-3-reliability.md) | L3-01 任务恢复；L3-02 退款对账；L3-03 评测发布 | 用失败注入和数据库断言验证关键保证 | 每实验 60–90 分钟 |
| [参考答案](solutions.md) | 九个新增测试示例与解释 | 对照输入、预期状态和负例，检查自己的推理 | 作业完成后再阅读 |

需要准备面试的读者可以先完成 L2-02、L3-01、L3-02，再结合[项目展示材料](../showcase/README.md)组织讲解；前置概念仍应回到前两层补齐。课堂主路径使用 Python、本机 SQLite 和受控模型，不要求 Docker、GPU 或真实模型密钥；临时数据与学习检出内保留数据的区别见[环境准备](setup.md)。

## 每个实验怎样完成

1. 阅读“问题”和代码入口，先写下正例与负例的预期结果。
2. 执行“基线验证”中的现有命令，记录测试名、实际结果和代码版本。
3. 在自己的学习分支中完成“动手作业”。作业要求新增的 `test_learning_*` 方法尚不属于仓库基线，用参考答案中的命令验证前须先把方法加入指定测试类。
4. 对照数据库、工具调用记录或引用字段解释结果，不仅观察回答文本或 `OK`。
5. 保存一页实验记录与测试改动。教师按下面的标准验收。

| 验收项 | 必须交付的内容 |
|---|---|
| 可复现 | Git 提交号、Python 版本、执行命令、实际测试结果 |
| 可解释 | 一张调用或状态转换图，以及关键代码入口 |
| 有反例 | 至少一个被拒绝的输入或中断场景，说明副作用是否发生 |
| 有改动 | 本实验新增测试的 diff，解释为什么覆盖了新的输入组合 |
| 有边界 | 说明该实验没有验证的模型能力、外部服务或部署条件 |

只运行已有测试完成的是基线观察。作业的新增测试、讲解和最终报告由学员实际完成，不把本仓库附带的答案写成自己的新成果。

## 结课任务

选择“客户修改诉求后重新确认”或“退款响应丢失后对账”作为主线，交付五分钟演示、状态图、两个负例测试，以及一页验证报告。报告需分别列出模型替身、本机 HTTP、SQL 持久化、浏览器和真实外部服务的使用情况。演示操作沿用[五分钟指南](../guides/five-minute-demo.md)，展示资料组织方式见[演示材料](../showcase/demo.md)。

进阶选做可参考[双数据库与迁移配置](../guides/configuration.md)、[Compose 验收](../operations/compose-acceptance.md)和[持续负载](../operations/sustained-load.md)。这些任务需要各自的 PostgreSQL 或容器环境，不是九个主实验的前置条件，也不能把本机观测外推为生产容量。

## 评测范围

课程聚焦项目搭建与技术探索，使用合成政策、受控模型和临时测试数据。真实人工审核、真实模型效果评测和生产环境验证属于后续自费验证，均在[当前项目范围](../evaluation/acceptance.md#project-scope)之外，不作为课程结课条件。

原 32 题尚未完成真实人工审核，原冻结的 16 题保留集保持未运行。测试中的合成审核账号、批准记录和 `live` 字段只用于检查代码分支，不计入真实审核进度；不要修改原评测数据、绕过门禁或调用付费模型来完成课程。
