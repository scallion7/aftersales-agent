# 项目展示与面试材料

[文档中心](../README.md) · [当前验收](../evaluation/acceptance.md) · [分层教学](../learning/README.md)

AfterSales Agent 是面向电商售后的 Agent 应用工程项目。本目录把业务问题、设计取舍、可运行演示和验证证据组织成一套展示材料，维护者为 [scallion7](https://github.com/scallion7)。适合大模型应用、Agent 与 AI 后端方向的简历和技术交流。

当前项目聚焦系统搭建、技术探索与受控工程验证。人工审核、真实模型效果评测和生产环境验证为**后续自费验证，当前项目范围外**，具体状态与条件见[项目范围](../evaluation/acceptance.md#project-scope)。

## 按使用场景选择

| 场景 | 阅读和使用顺序 | 交付物 |
|---|---|---|
| 快速了解项目 | [项目卡](project-card.md) → [系统架构](../architecture/overview.md) | 一页项目介绍、业务主线、能力与证据 |
| 准备简历 | [简历表述](resume.md) → [工程演进](../CONTRIBUTIONS.md) | 面向大模型应用与 Agent 开发的推荐版、后端侧重和短版 |

首次准备建议按项目卡、简历、讲解、演示的顺序完成一次自查。把简历中每条表述对应的代码打开，至少能解释一个失败场景和一项实际断言，再选择适合岗位的内容。

## 一条贯穿讲解的业务线

用户提出退货需求，系统先核对订单归属并查政策，分轮补齐材料，生成绑定具体参数的提案。用户确认后才能创建工单，需要审批时进入人工流程。执行结果不明则保留原业务键查单，客服接管后旧任务不能继续登记新的自动调用。演示步骤、可观察结果和故障处理见[演示材料](demo.md)。

介绍时先讲这条业务线，再按听众兴趣展开检索、执行恢复或评测发布。技术细节通过[项目卡的证据映射](project-card.md)定位，避免逐个罗列目录和组件。
